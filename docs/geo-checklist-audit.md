## 1. 미충족 — 코드로 해결 가능 (권장 순)

### C1. canonical URL 전 페이지 누락 ★최우선
- 기준: ② 기술 SEO — "페이지마다 운영 도메인의 canonical URL이 정확하다"
- 실측: `curl https://www.arthdental.com/treatments/root-canal` → `<link rel="canonical">` **0건**. `app/layout.tsx`·각 페이지 metadata에 `alternates.canonical` 없음.
- 영향: `arthdental.com` / `www.arthdental.com` 두 호스트가 살아 있고(현재 www로 301) 파라미터가 붙은 URL도 그대로 색인될 수 있어, 색인 분산과 AI 인용 시 URL 불일치를 만든다.
- 처리: `layout.tsx`에 `alternates: { canonical: './' }` 를 두면 App Router가 페이지별 절대 URL을 자동 생성한다. (작업 10분)

### C2. 개인정보처리방침 등 정책 페이지 부재
- 기준: ② 홈페이지 정보구조 — 필수 페이지에 "정책: 개인정보 처리, 필요한 동의·비급여 안내"
- 실측: `app/` 하위에 privacy/policy/terms 라우트 **없음**.
- 영향: E-E-A-T의 Trust 축 결손. 의료기관 홈페이지는 개인정보처리방침 게시가 사실상 필수.
- 처리: `/privacy` 정적 페이지 + Footer 링크. 문안은 병원 확인 필요(B3와 묶임).

### C3. Footer에 사업자·의료기관 정보 없음
- 기준: ② 홈페이지 정보구조 — "사업자·의료기관 정보와 개인정보 처리 안내가 필요한 범위에서 보인다"
- 실측: `components/Footer.tsx`는 주소·전화·링크 3개·저작권만. 대표자명·사업자등록번호·의료기관 명칭 표기 **없음**.
- 처리: Footer 확장 (값은 병원 확인 — B1).

### C4. 진료 페이지에 검수자·갱신일 미표시
- 기준: ③ 진료·시술 페이지 "출처·갱신일: 의학적 근거와 마지막 검수일" / ⑤ E-E-A-T "Who: 작성자와 의료진 검수자가 누구인지 명확하다"
- 실측: `CONTENT_UPDATED` 상수는 sitemap·JSON-LD(`lastReviewed`)에만 쓰이고 **화면에는 노출 0건**.
- 영향: 가이드가 발행 게이트로 지정한 항목("의료진 검수자와 검수일이 없으면 발행하지 않는다"). AI 답변이 신뢰 근거로 읽는 신호.
- 처리: 상세 페이지 하단에 "이 내용은 OOO 원장(전문의)이 검수했습니다 · 최종 검수 2026-08-28" 한 줄. 과목별 검수자 매핑은 `specialist` 필드 재사용 가능(현재 신경치료만 있음 → 7과목 확장).

### C5. 부작용·주의사항의 가시성 부족
- 기준: ③ "부작용·주의사항: 효과 정보와 비슷한 가시성으로 제공"
- 실측: `lib/copy.ts` 전체에서 "부작용" **1회**(미백 FAQ 추정). `aftercare`는 사후 주의사항이라 부작용과 다름.
- 처리: 과목별 `risks` 필드 신설 + 효과 서술과 같은 위계로 배치. 내용은 의료진 확인 필요(B2).

### C6. 화면 breadcrumb 부재
- 기준: ② "탐색 경로가 필요한 사이트에는 Breadcrumb과 `BreadcrumbList`가 있다"
- 실측: `BreadcrumbList` 스키마는 v1.56에서 추가 완료 ✓ / 화면상 빵부스러기 UI는 **없음**.
- 처리: 상세 페이지 상단에 `홈 › 진료과목 › 신경치료` 한 줄. 스키마와 화면 일치(가이드 ④ "화면 본문과 일치" 요건).
